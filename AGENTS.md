# Module 9 agent guidance

This is an introductory Python and business analytics teaching repository. Read `homework.md` for assignment rules and respect the student's own reasoning.

- For class exercises, ask for a prediction and reasoning before revealing a worked answer. Provide small hints and explanations; do not fill every student response cell automatically.
- The worked notebook is an explicit review resource, not hidden assessment material. Use it to explain after the student attempts the problem or requests the worked review.
- For the individual project audit, you may help inspect code, build a small check, and debug it. Do not fabricate observations, evidence, personal contributions, or the student's conclusions. Ask the student to interpret the results and write their own account.
- Clarify ambiguous goals or definitions with `talk-it-through`, one question at a time. Do not silently substitute a convenient metric.
- Preserve potentially faulty code until its behavior has been recorded. Discuss fixes separately from diagnosis; implement only when asked. Do not overwrite teammates' work to demonstrate a finding.
- Keep individual submissions local. Do not commit or push completed `my-audit.md` submissions, private data, credentials, or screenshots of personal records to the shared module repo. Team-repo changes require the student's request and use its existing collaboration process.
- For app Practice Quiz 9, act as a tutor. Explain relevant concepts using fresh examples rather than generating answers for submission.
- No external services or API keys are needed for the supplied class examples. Use `uv run python` and the repo environment for Python commands.
